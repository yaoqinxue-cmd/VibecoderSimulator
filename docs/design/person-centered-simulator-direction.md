# Vibe Coding 模拟器人生选择版方向草案

日期：2026-05-24

## 核心修正

Vibe Coding 模拟器的主角不应该是一个项目，而应该是一个人。

更准确的产品命题是：

> 你从今天开始 Vibe Coding。每一次选择都不只是改变作品，也在改变你成为什么样的人。

所以第一版不是“做一个项目从 0 到 1 的模拟器”，而是“AI 时代个人命运分化模拟器”。项目会出现，而且应该出现很多次，但它们只是玩家人生轨迹上的证据：你做过什么、逃避过什么、沉迷过什么、真正学会过什么。

## 为什么这个方向更好

只做单项目模拟有三个问题：

- 吸引力窄：玩家容易把它理解成一个带笑话的项目管理小游戏。
- 想象空间小：结局多半围绕产品成功、失败、维护灾难，重复度高。
- 传播弱：玩家更愿意分享“我变成了什么人”，而不是“我这个虚构项目怎么样了”。

做人生命运模拟有三个优势：

- 代入更强：Vibe Coding 本身正在改变很多人的身份感、能力边界和欲望结构。
- 结局更丰富：成功、沉迷、转型、清醒、荒诞、成名、破产、成长都能成立。
- 更有启发性：游戏可以让玩家反思自己如何使用 AI，而不是被工具使用。

## 游戏类型定位

建议定位为：

> 一款关于 AI 时代个人成长、沉迷、创造和自我误判的幽默人生模拟器。

参考组合：

- BitLife 的人生阶段推进。
- Reigns 的短决策和少量指标。
- Universal Paperclips 的系统逐步失控。
- The Password Game 的递增荒诞。
- Infinite Craft 的惊喜发现和传播结局。

不要定位为：

- 项目管理模拟器。
- 程序员考试。
- AI 工具教程。
- 纯大语言模型自由文本冒险。

## 核心循环

每一轮选择都回答一个问题：

> 这件事会让你更接近哪一种人？

推荐循环：

1. 出现一个生活或创作事件。
2. 玩家做一个短选择。
3. 立即看到幽默反馈和指标变化。
4. 系统记录一个人生痕迹：作品、习惯、关系、声誉、欠下的钱和人情、能力、执念。
5. 后续事件根据这些痕迹分化。
6. 最终汇总成一个身份结局。

## 单屏回合交互

主流程的每一个问题都应该占满整个屏幕，形成“一屏一问一回合”的节奏。玩家不需要上下滑动来读完题目，也不需要在页面里找下一步在哪里；他只需要看完当前事件、做选择、看到反馈，然后进入下一屏。

这个设计有三个价值：

- 沉浸感更强：每个问题都像游戏里的一个回合，而不是表单里的一道题。
- 节奏更干净：玩家只处理当前选择，不被上一题、下一题和长文档干扰。
- 截图更清楚：每一屏天然就是一个完整的情境，适合被记住和转述。

单屏结构建议：

- 顶部：当前阶段、回合编号、轻量状态灯。
- 中部：事件文本，只写一个清晰情境，不写长段背景。
- 下方：2 个主选择，少量关键场景可用 3 个选择。
- 角落：四个指标的轻量变化预告或当前状态，不抢主问题。

交互约束：

- 主流程事件卡使用整屏布局，按 `100dvh` 设计，不把核心内容放到滚动区域里。
- 每个问题的正文、选择和必要状态信息必须在手机首屏内完整可见。
- 文案宁可拆成下一张事件卡，也不要让单题变成长阅读。
- 结果页首屏先完整呈现结局标签、短注释和核心指标；更长的结果描述可以用模块切换或折叠层承载，避免最后突然变成需要滚动阅读的长文章。

事件不要只来自项目本身，还要来自生活周边：

- 深夜灵感。
- 新工具发布。
- 朋友问“你这个到底能干嘛”。
- 老板发现你两小时做完了一周的活。
- 第一个用户夸你。
- 第一个用户骂你。
- API 账单来了。
- 你开始给 AI 助手写需求文档，而不是给人解释需求。
- 你忘了自己最初想做什么。
- 你第一次因为 AI 做出了以前不敢做的东西。

## 第一版指标

建议只展示四个指标，避免认知负担：

| 指标   | 含义                                                 | 过低风险                       | 过高风险                       |
| ------ | ---------------------------------------------------- | ------------------------------ | ------------------------------ |
| 推进感 | 产出速度、热度、行动惯性                             | 什么都想，什么都没发           | 连发 17 版但没人知道发生了什么 |
| 判断力 | 理解需求、知道什么该做什么该删、识别 AI 编出来的内容 | 被 AI 编出来的内容和模板牵着走 | 过度分析，迟迟不上线           |
| 主体性 | 清醒度、自主选择、是否仍由你决定方向                 | 工具和反馈替你决定人生         | 过度控制，拒绝借助工具         |
| 稳定度 | 生活节奏、关系、现金流、健康                         | 烧光时间、钱和信任             | 太稳，错过探索窗口             |

这四个指标应该互相拉扯，而不是形成单一最优解。好的结局来自组合，不来自全满。

## 阶段结构

第一版一局 15-20 分钟，分三幕：

### 第一幕：第一次开挂

玩家从现在开始 Vibe Coding。重点是爽感、惊喜和失控的萌芽。

典型事件：

- 你让 AI 写了第一个小工具，它居然跑起来了。
- 你决定要不要理解这段代码。
- 你把演示版本发给朋友，朋友问是不是已经可以融资。
- 你第一次发现“能做出来”和“知道自己做了什么”不是一回事。

### 第二幕：世界开始回应

作品、他人反馈和现实成本进入游戏。重点是让玩家意识到选择会改变社会关系。

典型事件：

- 用户来了，但他们用法完全不是你想的那样。
- 同事发现你效率暴涨，开始把模糊需求都丢给你。
- 你的视频火了，评论区开始要求教程。
- API 账单、隐私问题、问题反馈、客服邮件一起出现。

### 第三幕：你变成了谁

玩家开始进入身份分岔。重点不是项目能否上线，而是玩家最终的人生状态。

典型事件：

- 你要不要辞职全职做这个。
- 你要不要把真实用户反馈交给 AI 助手总结。
- 你要不要承认自己其实没有看懂核心逻辑。
- 你要不要把产品砍小，让它真的可靠。
- 你要不要开始卖课、写帖、做社群。

## 结局方向

结局应该是“人的状态”，不是单纯项目状态。第一版可做 8-12 个。

| 结局           | 触发倾向                                 | 调性                                                           |
| -------------- | ---------------------------------------- | -------------------------------------------------------------- |
| 真有人在用！   | 推进感高，判断力高，主体性稳，稳定度未崩 | 真的做出了很牛逼的产品，代价是开始认真写清楚“做到什么才算完成” |
| 无聊但OK       | 判断力高，稳定度高，推进感中等           | 没爆火，但你活得像个下个月还能继续的人类                       |
| 复杂意图解构师 | 判断力高，主体性高，推进感中低           | 没有变成大师，但学会了不把模糊当灵感                           |
| 自动化上瘾者   | 推进感高，主体性低，稳定度低             | 你的工具链已经开始对你进行绩效管理                             |
| 录屏演示之王   | 推进感高，判断力低，外部声誉高           | 只要不点开产品，一切都很完美                                   |
| 成功人设       | 声誉高，作品一般，主体性摇摆             | 产品一般，但标题真的很懂增长                                   |
| 被账单追杀     | 推进感高，稳定度低，账单事件多           | 用户越喜欢，你越紧张                                           |
| 闷声做完验证   | 推进感中等，判断力高，稳定度高           | 没赢热搜，但赢了下个月还能继续                                 |
| 指令套娃get    | 主体性极低，AI 助手事件链过多            | 人生进入了自动驾驶，但目的地是自动生成的                       |
| 肉体即将下线   | 推进感高，稳定度极低                     | 产品快上线了，你也快下线了                                     |
| 工具收藏家     | 新工具选择过多，作品痕迹少               | 你的生产力系统终于需要一个生产力系统                           |
| 老板竟是我     | 用户/收入事件高，判断力中高，生活失衡    | 你做成了产品，然后产品开始安排你的人生                         |

## 结果页设计

最终不做单独分享卡，也不在第一版引入路径复现链接。游戏最后只给玩家一个结果页：它可以自然截图、转述和传播，但不需要额外的传播系统。

结果页应包含：

- 你的 Vibe Coding 结局标签。
- 一句短注释。
- 四个指标。
- 代表作品列表。
- 三个关键人生选择。

示例：

> 你成为了：自动化上瘾者  
> 你的工具链已经开始对你进行绩效管理。  
> 你做出了 12 个工具，其中 9 个用来管理另外 3 个工具。

## 视觉风格方向

整体风格建议偏复古未来主义：有旧式电脑、航天控制台、企业内网体检报告的秩序感，但内容本身是荒诞的。页面看起来越认真，玩家读到“产品开始安排你的人生”时越好笑。

- 结构上使用网格、编号、状态灯、指标条、字段标签和模块化分区。
- 色彩上避免普通赛博朋克和大面积紫蓝渐变，优先使用深色底、低饱和灰、荧光绿或琥珀色点缀。
- 质感上可以有轻微扫描线、终端字体、细线框和老式系统提示，但不要影响可读性。
- 气质上像一份“正式到有点可疑”的人生报告，而不是抽卡页、排行榜或营销海报。

## 第一版范围

第一版建议范围：

- 单一初始身份：今天开始认真 Vibe Coding 的普通人。
- 不做职业选择大地图。
- 不把真实大语言模型放到每次选择的主路径。
- 40-60 张事件卡。
- 4 个指标。
- 8-12 个身份结局。
- 结局页。
- 项目记录最多展示 3-5 个，不做完整项目经营系统。

这能保留“人生模拟器”的想象力，同时避免第一版变成一个不可控的大系统。

## 设计原则

- 每个选择都要同时改变作品和人。
- 笑点来自机制后果，不只来自文案段子。
- 结局要让玩家觉得“这可能真的是我”。
- 不说教，不惩罚探索。
- 成功结局必须存在，而且要有真实代价。
- 沉迷结局要好笑，但不能把玩家当傻子。
- 技术梗要有表层解释，让非工程玩家也能理解。
